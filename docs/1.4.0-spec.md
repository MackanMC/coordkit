# CoordKit 1.4.0 — Sharing & organising

**Status:** implemented in 1.4.0  
**Milestone:** 1.4.0  
**Theme:** make waypoint lists portable and manageable.

## Goals

- Move waypoints between worlds, instances and players without hand-editing
  `config/coordkit.json`.
- Share one waypoint or a whole list through the clipboard, including
  chat-friendly single-line codes.
- Keep large lists usable with groups, search, filters, sorting and bulk actions.
- Preserve 1.3.0 configs and behaviour. A 1.3.0 client must still be able to read
  a 1.4.0 config, even if it ignores the new fields.

## Non-goals

- Server-side commands, server plugins or automatic server sync.
- Cloud accounts or third-party sync.
- Nested folders. Groups are a single flat label.
- Per-waypoint icons, timestamps or arrival alerts.
- A native operating-system file picker. 1.4.0 uses the clipboard plus a managed
  `exports/` folder; a file picker can come later.

## Data model

`Waypoint` gains:

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `group` | string | `""` | Trimmed, 0–24 characters, case-insensitive uniqueness, original case preserved. Empty means ungrouped. |

`CoordKitConfig` gains:

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `configVersion` | int | `2` | Missing means 1 (pre-1.4.0). Written as 2 by 1.4.0. |

No stable waypoint ID is added in 1.4.0. Duplicate detection uses
name + dimension + scope + coordinates, which is sufficient for additive imports
and avoids inventing IDs for old configs.

### Config migration

- A missing `configVersion` is treated as 1 and upgraded to 2 on the next save.
- A missing `group` becomes `""`.
- All 1.3.0 waypoints load unchanged and remain ungrouped.
- Existing `world`, `autoDeath`, colour and visibility behaviour is unchanged.
- Older CoordKit versions can still read the file. If an older version saves it,
  the new fields are lost; document this in the changelog.

## Export format

### JSON envelope

UTF-8, pretty printed, safe to hand-edit:

```json
{
  "format": "coordkit.waypoints",
  "version": 1,
  "exportedAt": "2026-10-25T20:00:00Z",
  "waypoints": [
    {
      "name": "Base",
      "x": 120.5,
      "y": 64.0,
      "z": -30.25,
      "dimension": "minecraft:overworld",
      "color": 4632774,
      "visible": true,
      "world": "sp:my-world",
      "autoDeath": false,
      "group": "Home"
    }
  ]
}
```

Rules:

- `format` must be `coordkit.waypoints`; `version` is 1 for this format.
- Maximum 500 waypoints per import.
- JSON imports are all-or-nothing: one invalid entry rejects the whole file with a
  clear error.
- Waypoint fields use the same names as the config file.
- `autoDeath` may be present for fidelity but is always imported as `false`, so an
  imported death waypoint becomes a normal waypoint.
- Unknown fields are ignored so newer exports remain importable where possible.

### Validation

| Field | Rule |
| --- | --- |
| `name` | Trim; empty becomes `Waypoint`; longer than 32 characters is truncated to 32. |
| `x`, `y`, `z` | Finite and within ±30,000,000. |
| `dimension` | Valid `Identifier`; otherwise the entry is invalid. |
| `color` | Masked to 24 bits; invalid or missing uses the default colour. |
| `visible` | Missing defaults to `true`. |
| `world` | Empty, `sp:<save>`, or `mp:<address>`; normalised with `WaypointScope.normalizeWorld`. Anything else is invalid. |
| `group` | Trim; longer than 24 characters is truncated to 24. |
| `autoDeath` | Always imported as `false`. |

### Export sets

The export screen offers:

- **All waypoints**
- **Visible here** — waypoints currently visible in this world, including global
  waypoints
- **Visible only** — waypoints with `visible = true` in any world

Export writes
`config/coordkit/exports/coordkit-<yyyyMMdd-HHmmss>.json` and can also copy the
same JSON to the clipboard. The screen shows the full path and offers a button to
open the exports folder.

## Share code

One waypoint per line, designed for chat and Discord:

```
CK1;<name>;<x>;<y>;<z>;<dimension>;<color>;<world>;<visible>
```

- `name` and `world` are percent-encoded as UTF-8 (including `%` itself).
- Coordinates use `Double.toString`, so values round-trip exactly.
- `color` is an unsigned 24-bit decimal value.
- `visible` is `1` or `0`.
- `autoDeath` is not encoded; imported waypoints are never auto-death waypoints.
- Empty world is an empty field.

Example:

```
CK1;Base;120.5;64.0;-30.25;minecraft:overworld;4632774;sp%3Amy-world;1
```

The manager's **Share** action copies one code. **Export → Copy share codes**
copies one code per line. Import accepts a JSON envelope, one share code, or
several share codes separated by newlines.

Minecraft chat rejects messages over 256 characters. If a code exceeds 240
characters, CoordKit still copies it (for Discord or a file) but warns that it is
too long to paste into chat in one message. The 32-character name limit keeps
normal codes well under the limit.

## Import behaviour

The import screen reads the clipboard automatically and offers **Refresh** and
**Import latest export**. It shows a preview before applying anything:

- total entries
- valid entries
- duplicates
- invalid entries, with the first few reasons

### Scope policy

| Policy | Behaviour |
| --- | --- |
| **Keep original scope** (default) | Keep the `world` value from the file or code. |
| **Current world** | Replace `world` with the current world key. Disabled when the world is unknown. |
| **Global** | Set `world` to `""`. |

### Duplicates

A duplicate has the same normalised name (trimmed, case-insensitive), dimension,
scope after applying the policy, and coordinates rounded to two decimals.

- Duplicates are skipped, never overwritten in 1.4.0.
- The result reports `imported`, `skipped duplicates` and `invalid`.
- Imports are additive and never delete existing waypoints.
- A JSON file with a wrong `format` or an unsupported `version` changes nothing.

Success uses action-bar feedback for the short summary and chat for the detailed
path/counts. Errors are shown in chat with a reason.

## Manager organisation

### Search, filter and sort

- Search box matches waypoint name and group, case-insensitive.
- Scope filter: **Visible here** (including global) or **All worlds**.
- Group filter: **All groups**, **Ungrouped**, or a specific group.
- Sort: **Name**, **Group then name**, or **Distance from player**.
- Pagination is preserved; changing a filter, sort or query resets to page 1.
- Rows show a small group label when a group is set.

The filter/sort state is in-memory and resets when the screen is reopened. It is
not written to the config.

### Groups

- Groups are edited in the waypoint editor with a free-text field and suggestions
  from existing groups.
- Group names are trimmed to 24 characters and compared case-insensitively.
- The manager's **Groups…** button opens a screen that lists every group with its
  waypoint count. **Rename** updates every waypoint in that group; **Delete**
  clears the group on those waypoints and never deletes waypoints.
- A group with no waypoints disappears from the filter automatically.

### Bulk actions

- A `[ ]` / `[x]` select button per row enables multi-select.
- **Select all** selects every waypoint matching the current search and filters,
  not just the visible page.
- Actions: **Clear**, **Show**, **Hide**, **Delete**. The shared bottom row
  switches between these and the normal Export/Import/Groups buttons whenever a
  selection exists.
- Bulk delete requires a second click, with the count in the button, tooltip and
  action bar.
- Selection is cleared when filters change, when the screen is reinitialised
  after returning from a sub-screen, and when the screen closes.

## Screens and feedback

- The waypoint manager gains **Export…**, **Import…** and **Groups…** buttons
  plus per-row **Share** and selection actions.
- New screens follow the existing screens' plain layout and keyboard navigation.
- Action bar: immediate success/failure. Chat: file paths, import counts, and
  validation details.
- Clipboard and file failures are caught and reported; they never crash the client.

## Deviations from the proposed spec

These choices changed during implementation and are reflected above:

- **Cycle buttons instead of dropdowns.** The manager's scope, group and sort
  controls, the export set/format selectors and the import scope policy are
  single buttons that cycle through their values. They fit the fixed-height
  manager at small GUI scales without a popup widget.
- **A dedicated Groups screen.** Rename and delete live in **Groups…** with a
  separate **Rename Group** prompt rather than in the manager's group filter.
  Delete arms on the first click and confirms on the second, naming the member
  count.
- **Two-click confirmations instead of modal dialogs.** Per-row delete, bulk
  delete and group delete use an armed second click with the count shown in the
  button, tooltip and action bar.
- **Suggest cycles groups.** The editor's group field has a **Suggest** button
  that cycles existing groups matching what has been typed, instead of a
  suggestion dropdown.
- **One shared action row.** With no selection the bottom row shows
  **Export… / Import… / Groups… / Select all**; with a selection it changes to
  **Clear / Show / Hide / Delete**. This keeps the manager height unchanged.
- **Literal UI strings.** New screens use Java string literals, matching the
  existing screens. `en_us.json` still contains only keybind names; moving all
  strings to translations remains separate cleanup.
- **Share codes carry no group.** `CK1` keeps its nine fields, so imported share
  codes arrive ungrouped. JSON exports preserve `group`; use JSON when the group
  label matters.
- **Selection clearing.** Selection also resets when the manager is
  reinitialised after returning from a sub-screen, not only on filter changes
  and close.

## Testing

### Automated

- Export/import JSON round-trip, including all waypoint fields.
- Share-code round-trip, including spaces, Unicode, `%`, semicolons and empty
  groups/worlds.
- Malformed JSON, wrong format/version, too many entries, NaN/infinite and
  out-of-range coordinates.
- Name/group truncation and invalid dimensions.
- Duplicate detection across scope policies.
- 1.3.0 config migration and the `group` default.
- Group rename/delete keeps waypoints.

### Manual

- 1.3.0 config opens with no changes; saving writes `configVersion` 2.
- Export in one singleplayer world, import in another with each scope policy.
- Export on a server and import in singleplayer, and the reverse.
- Share code through Minecraft chat and through the clipboard.
- Import malformed and over-500-entry files; confirm nothing changes.
- Bulk show/hide/delete, including "select all filtered" across pages.
- Group rename/delete with many waypoints.
- Clipboard unavailable/empty and read-only export folder.
- Old 1.3.0 jar can still read the 1.4.0 config (new fields ignored).

## Risks and mitigations

- **Clipboard differences on Linux/Wayland.** File export is always available as a
  fallback; failures are reported, not fatal.
- **Chat length limit.** Warn for codes over 240 characters and point users to
  export/copy instead.
- **Older clients drop new fields.** Documented; recommend all players update
  before sharing grouped lists.
- **Destructive bulk actions.** Checkbox selection is explicit, delete is
  confirmed with a count, and selection never survives a filter change.
- **Scope surprises.** Preview shows the resulting scope before import, and
  "Current world" is disabled when the world key is unknown.
